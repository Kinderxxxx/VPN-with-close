# Базовая настройка VPN-ноды (Ansible)

Подходит для входных и выходных нод. Поддерживаются Ubuntu 22.04 / 24.04 и Debian 12.

## Что делает плейбук

- обновляет систему, ставит базовые пакеты, синхронизацию времени (chrony), автообновления безопасности;
- создаёт админ-пользователя с входом только по SSH-ключу;
- настраивает файрвол UFW (закрыто всё, кроме SSH и портов из `firewall_public_ports`) и fail2ban;
- тюнит ядро под прокси-нагрузку: BBR, очереди соединений, буферы, conntrack, лимиты открытых файлов;
- ставит Docker из официального репозитория с ротацией логов;
- отключает вход под root и по паролю (отдельным шагом, см. ниже).

Саму ноду (агент панели с Xray/sing-box) этот плейбук не ставит: её настройки и секретный ключ выдаёт панель,
поэтому её роль добавим после развёртывания панели.

## Подготовка на вашем компьютере

1. Установите Ansible (Linux/macOS: `pipx install ansible-core`; Windows: через WSL).
2. Установите коллекции: `ansible-galaxy collection install -r requirements.yml`
3. Если нет SSH-ключа: `ssh-keygen -t ed25519`

## Подготовка проекта

1. Закажите сервер с Ubuntu 24.04 (или Debian 12) и добавьте свой публичный ключ при создании.
2. `cp inventory.ini.example inventory.ini` и впишите IP серверов.
3. В `group_vars/all.yml` вставьте публичный ключ в `admin_ssh_pubkey` (`cat ~/.ssh/id_ed25519.pub`).
   Если хостер выдал не root, а, например, `ubuntu`, поменяйте `ansible_user` в inventory.

## Запуск (порядок важен: так вы не потеряете доступ)

1. Первый проход без SSH-хардинга:
   ```
   ansible-playbook node.yml --skip-tags ssh
   ```
2. **В новом терминале** проверьте вход под админом:
   ```
   ssh opsadmin@IP_СЕРВЕРА
   sudo -n true && echo OK
   ```
3. Только если всё работает, применяйте хардинг (закроет root и пароли):
   ```
   ansible-playbook node.yml --tags ssh
   ```
4. В `inventory.ini` поменяйте `ansible_user=root` на `ansible_user=opsadmin`.
5. Перезагрузите сервер (`sudo reboot`), чтобы вступили в силу лимиты и обновления ядра.

Полезные варианты запуска:

- одна нода: `ansible-playbook node.yml -l entry-kz-1`
- пробный прогон без изменений: `ansible-playbook node.yml --check --diff`
- повторный запуск безопасен: Ansible меняет только то, что отличается от описанного.

## Что стоит знать

- **Порт SSH оставлен 22.** Смена порта на Ubuntu 24.04 требует отдельной возни с `ssh.socket`,
  а при входе только по ключам и fail2ban выигрыш небольшой.
- **Docker обходит UFW** для опубликованных портов. Поэтому ноду запускаем в host-сети или фильтруем
  трафик в цепочке `DOCKER-USER`; не полагаемся на правила UFW для контейнеров.
- Порты управления нодой открываются только для IP панели: после развёртывания панели
  заполните `panel_ip` и `firewall_panel_ports`.
- Значения тюнинга ядра в `templates/99-vpn-tuning.conf.j2` рассчитаны на сервер с 2+ ГБ RAM;
  на очень маленьких VPS их можно уменьшить.
